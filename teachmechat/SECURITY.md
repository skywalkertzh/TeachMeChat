# SECURITY · 安全策略

## 支持的版本

当前只维护 **0.2.x** 系列。0.1.x 及其更早版本不再接收安全修复。

## 报告漏洞

- **请私下报告，不要公开披露未修复的漏洞**（不要开公开 Issue、不要在社交平台发布细节）。
- 首选渠道：GitHub 仓库 **Security → Report a vulnerability** 私密报告（发布后请在仓库 Settings → Security 中开启 Private vulnerability reporting）。
- 若该入口尚未开启，请暂缓发送漏洞细节，并通过不含技术细节的普通 Issue 请求维护者开启私密报告；本项目不在公开文档中暴露私人邮箱。
- 报告中请尽量包含：受影响版本、复现步骤、最小示例（使用合成数据）、影响评估。**不要附带真实聊天记录、真实 API Key 或其他人的隐私数据。**

## 安全范围：以下问题算安全漏洞

- 数据越权外发：在用户未确认的情况下把聊天/媒体内容发送到非用户配置的地址，或超出已展示的授权范围。
- 写入微信数据库：任何对微信源库的写入、修改、删除或以其他方式破坏只读保证的行为。
- 凭据问题：API Key 明文落盘、被打印到日志/控制台、经 DPAPI 以外方式恢复或泄漏。
- 命令注入、路径穿越、任意文件写入/删除。
- 削弱只读检查与权限检查（例如绕过“连接微信”确认、绕过配置目录权限限制）。
- 供应链问题：在构建/依赖获取环节引入可疑代码或非预期下载。

## 以下问题不属于安全漏洞范围

- 用户自行导出、复制或传播的数据被第三方获取（数据流向由用户自己决定）。
- 模型服务商自身的安全事件、数据政策或其返回内容的准确性。
- 用户主动把 API Key 交给第三方代理服务造成的暴露。
- 微信官方数据库格式变化导致的读取失败（属兼容性问题，走普通 Issue）。
- 在已被恶意软件控制或已被越权的机器上运行本程序。

## 处置与承诺

- 我们会在合理时间内确认收到报告并评估影响；修复完成后再协调公开披露细节。
- **本项目不承诺漏洞赏金（bug bounty）**，也不承诺任何形式的报酬。请勿以赏金为前提提交报告。
- 修复节奏以本地优先、不引入新外发行为为前提；不接受以“修复”为名削弱隐私与只读边界的补丁。
